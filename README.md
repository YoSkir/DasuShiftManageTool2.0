# :deciduous_tree: 大樹藥局排班系統 :deciduous_tree:

大樹藥局排班系統是一套以 C#、.NET 10、Blazor 與 MudBlazor 開發的排班工具。系統會根據員工資料、班別設定、人力需求、休假、特休、固定班、指定班與個人偏好，自動產生 28 天的排班結果。

:arrow_forward:Demo：<https://dasushiftmanagetool2-0.onrender.com>

## :seedling:系統特色

- 以每半小時為單位計算人力，能處理早班、晚班與全班。
- 以每日分治法先建立當日所有合法班表，再串接成完整的 28 天班表。
- 以 DFS（Depth-First Search，深度優先搜尋）與回溯法窮舉每日可能的排法。
- 將**不可違反的規則**與**希望越平均越好**的偏好分開處理。
- 支援指定休假、特休、固定班、指定班、最低與最高人力、最低工時、最低休假天數及最高連續上班天數。
- 對最低工時、早班平均、連續上班天數與員工偏好進行加權，從合法候選中選出較適合的方案。

## :seedling:排班演算法

### 1. 每日分治法

系統不直接從第一天一路遞迴到整個月份，而是先針對單日建立所有可能的 `DailyShift`：

1. 建立當日的 `DfsShiftState`。
2. 從尚未達到最低人力的半小時開始處理。
3. 依序嘗試尚未排班的員工，以及設定允許的工作時數。
4. 當某個半小時達到最低人力後，移動到下一個仍未完成的時段，未達最高人力則繼續嘗試。
5. 當全日需求完成時，透過 `DcDfsResultSaver` 保存一個候選班表。
6. 回溯上一個排班動作，繼續搜尋其他可能性。

這種做法將「產生單日候選」與「串接多日班表」分離。單日候選數量通常比整月候選少很多，也能讓後續的條件篩選集中在每日結果上。

### 2. DFS 與回溯法

`EveryPossibleAssignTool` 使用深度優先搜尋探索排班樹。每一個節點代表一次員工與班別的分配，搜尋完成或不符合條件時，就撤銷最後一次分配並嘗試下一個選項。

排班狀態由 `DfsShiftState` 維護，包含：

- 每位員工每天的班別。
- 每半小時已安排的人數。
- 每位員工的累計工時。
- 每位員工目前的連續上班天數。
- 每週休假天數。
- 可供回溯的排班動作堆疊。

使用堆疊保存 `AssignMove`，可以在不複製整份班表的情況下快速還原狀態，降低 DFS 搜尋所需的記憶體。

### 3. 月度班表串接

建立完單日候選後，`DcDfsTool.AssignMonthly` 會從排班起始日開始逐日選擇候選：

1. 取得當日符合硬性規則的候選集合。
2. 使用 `IShiftFilter` 計算候選的優先順序或權重。
3. 從最高分候選中隨機選取一個班表。
4. 將班表寫入目前的月度狀態。
5. 繼續處理下一天。
6. 若後續條件無法滿足，放棄本次串接並重新嘗試。

目前月度串接最多嘗試 500 次(實測最高所需次數約為10次左右)；每次嘗試都會重新建立狀態與清除班別統計，避免上一輪結果污染下一輪。

### 4. 後處理與最低工時補足

完成每日串接後，系統會檢查員工是否達到最低月工時與最低月休假天數。若工時不足，會依序嘗試：

- 將不必要的休假改為可工作的班別，但不突破連續上班限制。
- 優先處理不會造成連上四天的日期。
- 將原本的短班延長為較長班別。
- 若仍無法達到最低工時，判定本次月度班表失敗並重新嘗試。

## :seedling:排班條件與篩選方式

排班條件分成兩類：**硬性條件**負責排除不合法候選；**軟性條件**不直接淘汰候選，而是透過加權讓較理想的方案優先被選中。

### 硬性條件：直接排除候選

以下條件在 `DcDfsTool.BasicFilter` 中逐一檢查：

| 條件 | 判斷方式 |
| --- | --- |
| 每半小時最低人力 | 比對 `DailyShift.StaffCount` 與該星期的 `EveryHalfHrMinWorkers`，任一時段不足即排除。 |
| 每半小時最高人力 | 產生與補足班表時使用 `EveryHalfHrMaxWorkers`，避免超過時段上限。 |
| 劃假 | 員工在指定休假日只能是休假狀態。 |
| 特休 | 特休日視為休假，不允許再安排工作班別；特休時數會在排班後計入。 |
| 指定班 | 員工在指定日期必須符合指定的開始時間與工作時數。 |
| 固定班 | 沒有被指定休假或指定班覆蓋時，必須符合每星期設定的固定班別。 |
| 最高連續上班天數 | 若員工已達 `MaxChainWorkDays`，當日不得再安排工作。 |
| 每週最低休假天數 | 週六、週日檢查目前休假數，避免在週期結束時低於 `MinWeekRestDays` 的需求。 |
| 每月最低休假天數 | 月度完成後檢查 `MinMonthRestDays`，不足時本次結果無效。 |
| 每月最低工時 | 月度完成後檢查 `MinMonthWorkHrs`，不足時嘗試後處理，仍不足則重新排班。 |

### 軟性條件：透過加權選擇

目前預設使用 `EasyWeightedFilter`。它不會直接刪除不符合偏好的方案，而是為候選累加分數，最後保留最高分的候選，再從最高分集合中隨機選擇：

| 加權項目 | 加分方向 |
| --- | --- |
| 員工偏好班別 | 符合員工偏好的開始時間或長班偏好時加分。 |
| 最低工時優先 | 優先安排目前累計工時較低的員工，且偏好全班或較長的班別。 |
| 連續上班天數 | 連續上班天數較高的員工若能休假則加分，降低連續工作過長的機會。 |
| 早班平均 | 優先將早班安排給目前早班次數較少的員工，讓早班分配更平均。 |

系統另外保留兩種篩選策略：

- `OrderFilter`：依序套用偏好班別、最低工時、連上四天與早班平均，符合條件的候選會取代原候選集合。
- `WeightedFilter`：依工時、早班次數、偏好、連續上班天數等項目計算較細的分數，取總分最高的候選。

這些篩選器都實作 `IShiftFilter`，因此可以依需求替換，不必修改月度排班流程。

## :seedling:設計模式與架構設計

### Strategy Pattern（策略模式）

排班流程中有多個可替換的演算法步驟：

- `IShiftGenerator`：替換整體排班生成策略，例如月度 DFS 或每日分治。
- `IAssignTool`：替換候選班別的搜尋與分配方式。
- `IShiftFilter`：替換候選班表的硬性篩選後排序或加權策略。
- `IResultSaver`：替換搜尋結果的保存方式，例如保存每日所有候選或保存排名結果。

這些介面讓搜尋、篩選與結果保存彼此解耦，也方便加入新的排班規則。

### Context Object（上下文物件）

`ShiftCreateContext` 集中保存一次排班所需的設定、員工、休假、固定班、指定班、偏好、目前狀態與篩選器。各演算法透過同一個 context 溝通，避免把大量參數逐層傳遞。

### State Pattern（狀態模式）

`IShiftState` 抽象出排班狀態的操作，`DfsShiftState` 負責實作 DFS 搜尋所需的狀態變更、統計與回溯。生成器不需要知道員工班表的內部儲存方式，只需要呼叫狀態介面。

### Repository / Data Access Abstraction

`IDataGetter` 將資料來源抽象化。核心排班演算法只依賴介面取得設定與員工資料，不直接依賴資料庫或 UI，因此可以替換成測試資料、正式資料來源或其他儲存方式。

### Dependency Injection

`ShiftCreateTool` 透過建構子注入 `IDataGetter`，讓資料存取與排班服務分離，也方便測試時注入 `TestDataGetter`。

## :seedling:一次排班的流程

```text
讀取設定與員工資料
        |
建立 ShiftCreateContext
        |
載入指定休假、特休、固定班與指定班
        |
DFS + 回溯：建立單日所有 DailyShift 候選
        |
逐日執行 BasicFilter，排除不合法候選
        |
IShiftFilter 加權或排序
        |
從最高優先候選中隨機選擇並串接
        |
檢查最低工時與最低休假
        |
後處理補足工時
        |
產生 28 天排班結果
```

## :seedling:目前設計限制

- 月度串接採用隨機選取最高分候選，因此每次執行可能得到不同但符合條件的結果。
- 若人員數量、可用班別或休假條件過於嚴格，可能找不到合法的月度組合。
- 目前排班週期以設定的起始日開始計算 28 天。
- `DcDfsShiftGenerator` 目前最多重試 500 次；若所有嘗試都失敗，會回報排班失敗。
